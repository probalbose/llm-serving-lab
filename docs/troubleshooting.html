Troubleshooting Commands

The uv, ruff, pytest, git, gh and llama-server commands used in llm-serving-lab, what each one does, and fixes for errors we have already hit. Every command has a Copy button.

Daily loop

The commands you run on almost every change, in order. Run them from the repo root (~/projects/llm-serving-lab).

uv run ruff check --fix . && uv run ruff format .

Lint and auto-fix what ruff can (import order, unused imports), then reformat the code (spaces, line breaks, quotes). Run before every commit.

uv run pytest -q

Run all tests quietly: one dot per passing test, details only for failures.

git status

Show what changed, what is staged and what is untracked (??). Check this before committing so no file is left behind.

git add -A && git commit -m "Describe the change" && git push

Stage every change (including new and deleted files), commit with a message, push to GitHub. The && chain stops at the first failure.

gh run watch

Follow the CI run for your latest push live in the terminal until it finishes. If it says "no in progress runs", the run already finished: use gh run list.

uv: Python, packages and the virtual environment

uv manages the Python version, the .venv folder and the locked dependency list (uv.lock). Everything runs through uv run so it uses the project's own versions.

uv --version

Check uv is installed. If you get "command not found: uv", install it with brew install uv.

uv sync

Make .venv match pyproject.toml and uv.lock exactly: installs missing packages, removes extra ones. This is the first step in CI. Run it after pulling or switching branches.

uv run python

Open a Python shell inside the project environment, so from serving_lab.client import RequestResult works.

uv run python scripts/one_shot.py

Run a script with the project environment. Plain python would use a different interpreter that doesn't have httpx or your package.

uv add httpx

Add a runtime dependency: updates pyproject.toml and uv.lock, then installs it.

uv add --dev pytest

Add a development-only dependency (tests, linters). It isn't installed for people who only use the package.

uv remove httpx

Remove a dependency from pyproject.toml, uv.lock and .venv.

uv lock

Re-resolve and rewrite uv.lock without installing. Use when pyproject.toml was edited by hand.

uv lock --upgrade-package httpx

Upgrade one package to the newest allowed version, leaving everything else pinned.

uv tree

Show the dependency tree: what depends on what. Useful when an unexpected package version appears.

uv pip list

List exactly which packages and versions are installed in .venv.

uv python list

Show which Python versions uv can see or has installed.

uv sync --reinstall

Reinstall every package from scratch. Use when .venv seems broken (strange import errors after an upgrade).

rm -rf .venv && uv sync

Nuclear option: delete the environment and rebuild it. Safe, because .venv is generated and not committed.

ruff: lint and format

ruff check finds problems (bugs, unused imports, style rules); ruff format rewrites layout. CI runs ruff check, so anything it reports fails the build.

uv run ruff check .

Report problems without changing files. Each finding has a code (I001, B905, RUF007) and [*] marks ones ruff can fix itself.

uv run ruff check --fix .

Apply all safe automatic fixes, then report what is left for you to fix by hand.

uv run ruff format .

Rewrite files into the standard layout: 4-space indents (no tabs), consistent quotes and line breaks.

uv run ruff format --check .

Report files that would be reformatted, without changing them. Good to add to CI later.

uv run ruff rule RUF007

Explain a rule in full: what it flags, why, and how to fix it. Replace RUF007 with any code from an error.

uv run ruff check src/serving_lab/client.py

Check one file only.

pytest: running tests

Tests live in tests/ and files must be named test_*.py. asyncio_mode = "auto" in pyproject.toml lets async def test_... work without decorators.

uv run pytest -q

Run everything, quiet output.

uv run pytest -v

Verbose: one line per test with PASSED or FAILED.

uv run pytest tests/test_result.py

Run one test file.

uv run pytest tests/test_result.py::test_no_tokens

Run one test function.

uv run pytest -k tpot

Run only tests whose name contains "tpot".

uv run pytest -x

Stop at the first failure. Handy when one bug breaks many tests.

uv run pytest --lf

Re-run only the tests that failed last time.

uv run pytest -s

Show print() output from tests (normally hidden).

git: local history

Everyday git for a single-branch repo. Commands marked careful rewrite history; only use them before you push.

git status

What changed, what is staged, what is untracked.

git diff

Show unstaged line-by-line changes. Add --staged to see what is about to be committed.

git log --oneline -10

Last 10 commits, one line each.

git log origin/main -1

The latest commit GitHub has. If it isn't your newest commit, you haven't pushed.

git ls-files

List every file git tracks. If a file CI needs isn't here, it was never committed.

git restore src/serving_lab/client.py

Throw away uncommitted changes to one file, back to the last commit. Cannot be undone.

git commit --amend --no-edit

Careful: add staged changes into the previous commit. Only before pushing; after a push it needs a force push.

git rm --cached path/to/file

Stop tracking a file but keep it on disk. Use when something (a model, .env) was committed by mistake, then add it to .gitignore.

grep -n $'\t' src/serving_lab/client.py

Find tab characters in a file (macOS grep needs $'\t' to mean a real tab). No output means no tabs.

gh: GitHub and CI from the terminal

gh talks to GitHub as you. Most CI debugging is: list runs, read the failed log, fix locally, push.

gh auth status

Check you are logged in and which account gh uses. If not, run gh auth login.

gh run list -L 5

Last 5 CI runs with status: ✓ passed, X failed, * running.

gh run view --log-failed

Show the log of the failed steps only. It asks you to pick a run; press Enter for the latest.

gh run view $(gh run list -L1 --json databaseId -q '.[0].databaseId') --log-failed | tail -30

Same, without the picker: the last 30 lines of the latest run's failed steps, usually where the real error is.

gh run watch

Follow the current run live until it finishes.

gh run rerun --failed

Re-run only the failed jobs of a run. Only useful for flaky failures (network blips); a real failure needs a code fix.

gh workflow list

List workflows GitHub knows about. If ci is missing, .github/workflows/ci.yml was never pushed.

gh browse

Open the repo page in your browser.

gh repo edit --description "..."

Change the repo's About description.

llama-server and the local model

Run the server in its own terminal tab and leave it running. Stop it with Ctrl-C.

llama-server -hf bartowski/Qwen2.5-7B-Instruct-GGUF:Q4_K_M --port 8080

Start the OpenAI-compatible server with our baseline model. The first run downloads about 4.7 GB. Ready when it prints "listening on http://127.0.0.1:8080".

curl -s localhost:8080/health

Health check. {"status":"ok"} means the model is loaded and ready.

curl -N localhost:8080/v1/chat/completions -H 'Content-Type: application/json' -d '{"messages":[{"role":"user","content":"Explain a KV cache in 3 sentences"}],"stream":true}'

Stream one chat completion. -N disables curl's buffering so you see chunks as they arrive. The last chunk carries the server's own timings.

lsof -i :8080

Show what is using port 8080. If the server won't start with "address already in use", an old one is still running.

kill $(lsof -t -i :8080)

Stop whatever process holds port 8080.
